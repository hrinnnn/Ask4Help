# 任务资产与服务器选择协议

## 目的

实验运行位置必须由任务资产、兼容环境、实时计算资源和结果持久化共同决定，不能默认选择最近使用的服务器，也不能只看空闲 GPU。

## 启动前资产清单

每个任务在占用资源前记录：

- 模型家族、immutable checkpoint 和 tokenizer/processor；
- 数据集、manifest、norm、prompt、action adapter 和 temporal mask；
- simulator/task source commit、任务资产和 success predicate；
- detector/calibration assets 与固定 seed manifest；
- 原生 Python/CUDA/Torch/模型环境；
- 预计 checkpoint、timeline、视频和日志空间。

每个项目必须注明实际服务器、绝对路径、持久化介质，以及文件是否可独立恢复。历史文档中的路径不是当前存在性证据。

## 候选服务器资源清单

对每台候选服务器分别检查：

- 实际空闲 GPU 数量、显存和现有进程归属；
- 可分配 CPU、RAM、磁盘余量与挂载状态；
- 任务所需 runtime 是否原生可用并通过 import/GPU smoke；
- immutable 输入是否已经同机，缺失部分的传输大小和恢复时间；
- 输出是否写入持久盘，以及实例替换后的恢复路径；
- 是否与已认领 pipeline 争抢资源。

## 选择原则

优先选择同时满足以下条件的服务器：

1. checkpoint、dataset/manifest 和任务资源已存在；
2. 模型环境已验证，且无需复制其他硬件上的 venv；
3. 有足够且确实空闲的 GPU/CPU/RAM；
4. 输出可直接持久化；
5. 不影响更高优先级的现有 pipeline；
6. 总恢复、传输和运行时间最低。

没有任何服务器满足全部条件时，选择缺失资产最少、恢复风险最低的服务器，只同步缺失的 immutable 输入。禁止因为资产缺失而重新训练已有 checkpoint，也禁止用其他任务 checkpoint 替代。

## 决策记录

长任务 manifest 或 `pipeline_state.json` 至少记录：

```json
{
  "placement_preflight": {
    "required_assets": [],
    "candidate_servers": [],
    "selected_server": "",
    "selected_reason": "",
    "rejected_alternatives": [],
    "resource_snapshot": {},
    "persistent_output_root": ""
  }
}
```

实例、挂载、GPU 分配或任务输入发生变化后，原 placement 结论自动失效，必须重新审计。

## 2026-08-22：StackCube token-wise PCA/OT 选择记录

### 5090

- 当前持久目录 `/data/ask4help-open-drawer` 只包含 OpenDrawer X-VLA runtime、dataset 和 checkpoints；`/data` 与 `/sdd` 是同一 `/dev/sdb1`，不是两份备份。
- 历史 StackCube 路径 `/data/zhaozhixuan` 当前不存在，因此无法访问 `ckpt-7500`、StackCube manifest 或先前 token-OT assets。
- GPU0/1 正在执行 OpenDrawer X-VLA 训练，使用 5090 会增加资产恢复和资源竞争。

### 阿里云 H20

- 两张 H20 均空闲，单卡约 96 GiB 显存。
- X-VLA 原生环境：`/root/.venvs/xvla-h20/bin/python`。
- X-VLA source：`/root/X-VLA-stackpyramid-clean`。
- StackCube base：`/root/xvla_stage2_inputs_priority/ckpt-7500`。
- X-VLA manifest：`/root/xvla_stage2_inputs/panda_stackcube_id_128.json`。
- 128 条 ID 数据：`/mnt/data/ask4help/datasets/lerobot/local/stackcube_id_128_visual_v1_20260722`。
- 既有 StackCube 结果与 checkpoint archives 位于 `/mnt/data/ask4help/results/xvla_stackcube_v1`。
- 环境归档：`/mnt/data/ask4help/environments/xvla-stage2-h20-20260813`。

### 结论

StackCube token-wise PCA/OT 资产重建与 passive failure-detection 评测选择阿里云 H20。它同时具备 immutable base、数据、兼容环境、空闲计算资源和持久化输出；5090 仅保留 OpenDrawer pipeline，不从其 checkpoint 做任何替代。
