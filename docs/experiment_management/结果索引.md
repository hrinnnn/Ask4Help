### 解释边界

这只完成了四方法比较中的 Internal-Feature PCA 一行，不是完整 StackPyramid robot-gated
DAgger baseline comparison。Stage 1/2/3 对应的 Diff-DAgger、Failure-Recovery、Offline BC
独立 OOD 数据、matched-budget 更新和共同评测仍缺失。它也不是完整的多介入时机 sweep；
timing 目录中的 DCA/EAS/DCE 是诊断代理，完整 paired state-snapshot timing utility 和多时机
对照仍列为后续实验。

### 四方法 gated-DAgger 对照（进行中）

已启动独立持久化总控，输出根为
`/data/zhaozhixuan/xvla_stackcube_data/stackpyramid_gated_dagger_four_method_comparison_v1_retry1_retry2/`。
四行方法为 Internal-Feature PCA、Diff-DAgger、Failure-Recovery、Offline BC；共同基座为
`ckpt-10000`，每个 Stage 的四种收集使用同一交替 ID/OOD seed manifest，训练为 1:1
source-balanced、正确 temporal mask、2000 steps、每 500 保存，最后统一做 100 ID + 100
对应 Stage OOD policy evaluation。专家低层动作总量会在四组收集完成后按最大共同可达预算匹配。

截至当前记录，Diff 独立 ID calibration 已完成；Stage 1 的 Bridge-PCA、Offline-Oracle
和 Failure-Recovery 已各完成 100 条。原始 Diff 目录仅完成 73/100，未进入训练；当前在全新
`collections/stage1_ood/diffdagger_retry2/` 中恢复，恢复器会在完成后自动推进后续阶段，尚无可进入论文主表的四方法最终数值。总控完成后，应直接读取该根目录的
`comparison.json` 与 `comparison.md`，并同时核对四方法的 `collections/`、`training/`、
`evaluation/` 以及视频数量；不要把旧 PCA 分支结果与新方法混成一张未经预算审计的表。

## 7. 尚缺结果

- X-VLA StackCube 目标位置 OOD timing study：retry2 已完成四组 matched-budget training、共同 checkpoint selection 和最终 100-ID/100-stage2-OOD evaluation。共同选择 step 2000；最终 success rate 为 ID：Immediate 73/100、Post-Grasp 58/100、Post-Lift 95/100、Failure-Recovery 71/100；stage2 OOD：52/100、10/100、4/100、30/100。完整结果根目录为 `/mnt/data/ask4help/results/xvla_stackcube_v1/temporal_mask_v2/stackcube_target_ood_timing_v1_retry2/`，汇总为 `final_evaluation_retry2/summary.json`。首轮 400 条 screen 与 retry1 故障记录仅保留追溯，不混入主结果。
- OpenDrawerRetrievePlace：128 条 ID Oracle、两个中间 takeover 验收、step-2000 ID base policy 及 ID/Handle/Grasp/Goal 各 100 条纯 policy baseline 已完成；detector、受控收集与 matched-budget 更新正在执行。训练根为 `/data/zhaozhixuan/Ask4Help-open-drawer/results/id_policy_training_v1/`，基线评测根为 `/data/zhaozhixuan/Ask4Help-open-drawer/results/id_policy_eval_v1/formal_100x4/`，数据和视频定义见 `docs/experiment_management/plans/OpenDrawerRetrievePlace_ID_and_stage_OOD.md`。
- X-VLA StackCube Stage 2 OOD：已完成，结果见上方 StackCube 条目。
- X-VLA StackPyramid：base policy 与 Internal-Feature PCA 在三个 Stage 上的收集、训练和评测已完成；四方法对照总控已经启动，Diff-DAgger、Failure-Recovery、Offline BC 的独立收集、共同 expert-action budget、训练和评测仍在进行。完整多介入时机 sweep 由另一个认领 Agent 独立推进，不能与本对照混写。
- DCA、EAS 及其与 learning utility 的相关性：未完成。
- UncoverSpherePlace：3x3 oracle gate、9/9 中间状态续接审计、三 split 正式采集、动作/帧边界与 temporal-mask 验收已完成。ID、Handle-OOD、Goal-OOD 各 128 条成功轨迹，正式输出为 `/data/zhaozhixuan/Ask4Help-uncover-sphere-place/outputs/collection_formal_stage_localized_v1_retry5/`，验证报告为 `collection_validation.json`；2-step ID SFT/reload smoke 已通过，ID base policy 已在 `id_sft_10000_retry4/` 完成 10000 步并保存 `ckpt-500` 至 `ckpt-10000`。`post_training_pipeline_v1_retry1/` 与全新 `post_training_pipeline_v1_retry2/checkpoint_selection/` 均已完整评测五个 checkpoint、各 20 条 ID rollout；retry2 的成功率全部为 0/20，写出 `BASE_POLICY_NOT_ACCEPTED`。因此 detector、gated collection、matched-budget 更新训练和最终评测尚未启动。旧 `post_training_pipeline_v1/` 的退出清理异常及 partial output 仅保留追溯，不混入主结果。
- Uncover 追加诊断：正式 ID 数据约 141,462 个动作锚点，10,000 步双卡 batch 8 约覆盖 1.1 个数据集遍历；同一 `ckpt-10000` 在 `execute_horizon=1/5/10` 的独立对照均为 `0/1`，且 mug parking 与 sphere grasp 均未发生。当前证据支持“长轨迹训练覆盖/任务难度不足”，不支持将失败归因于单一 5-step 重规划参数。诊断目录为 `diagnostics/control_horizon_ckpt10000_v2/`，不进入正式主表。
- 真机实验：未开始。
