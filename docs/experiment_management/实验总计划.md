## 每个 stage 的固定步骤

1. 冻结 ID/OOD 条件、seeds、oracle 与 base checkpoint。
2. 跑纯 policy rollouts，完成 failure-detection comparison。
3. 按同一部署流收集 PCA、Diff-DAgger、Failure-Recovery 与 Offline BC 数据。
4. 按专家低层动作数匹配预算，从同一 base checkpoint 更新策略。
5. 按《训练与持续运行协议》保存并评测共同训练节点；不得为不同方法分别挑选最佳 step。
6. 在固定 OOD seeds 上评测 Success Rate；mixed ID/OOD stream 另用于评价实际数据选择。
7. 更新结果索引，写明路径、完成标记、成功定义和已知限制。

Timing sweep 的条件、DCA/EAS/DCE 和启动门槛统一记录在对应子计划中，不在单个任务里另行修改。

## Agent 接力规则

1. 新 Agent 先按 `AGENTS.md` 顺序读完实验管理文档，再检查服务器上的实际完成标记。
2. 从总计划中选择第一个未完成且依赖已满足的任务。若显示 `未登记，认领前核实`，先核实没有现存负责人、总控或后台进程；若显示 `未认领`，仍需快速检查实际完成标记。确认后先写入认领信息，再开始任何实现或服务器操作。
3. 已认领任务不得重复执行。需要接管时先核实原 Agent、PID、总控状态、日志和完成标记，再把认领改为 `已接管`。
4. 复用共享协议；模型专属参数以该任务的脚本和 manifest 为准。
5. smoke 通过后由持久化总控程序自动执行同一任务内的收集、训练和评测，无需逐阶段重复询问；心跳只监督和恢复总控，不以单个阶段结束为完成。
6. 只有任务定义、指标定义或预算需要改变时才暂停请求确认；一般运行错误应先诊断和恢复。
7. 每完成一个阶段，立即更新本文件状态和《结果索引》，再继续下一阶段；整项任务结束或释放时同步清理认领信息。

若一个总计划条目包含多个可独立并行的子任务，先在对应子计划中拆出子任务认领表，再按最小独立单元认领；不得用一个宽泛的父任务认领阻塞所有并行工作，也不得在没有子任务登记时多人同时修改同一条 pipeline。
